## Context

`ui/index.html`（约 1900 行）是自包含单文件 UI：内联 qrcodegen 库 + 应用层 JS，被 DBX 宿主以沙箱 `srcdoc` iframe 加载，也可脱离宿主在浏览器独立预览。现状为 `main { width: min(600px, 100%) }` 单列，无媒体查询。应用层关键函数：`generate()`（实时渲染入口，300ms 防抖）、`updateActionButtons()`（导出按钮禁用态）、`buildPayload()`（按页签构建载荷）、`applyLocale()`（i18n）、`switchTab()`。历史、确认弹窗、样式盒逻辑本次不动。

约束：一切必须内联（无外部 src/href）；沙箱无剪贴板/下载保证（已有降级路径）；权限仅 `host.storage`；明暗主题与 zh/en 双语必须同步覆盖。

## Goals / Non-Goals

**Goals:**
- 桌面 ≥900px 双栏，实时反馈回路（输入 ↔ 预览）闭合
- 三个页签统一的容量计数与接近上限警示
- 空态/错误态上下文化：示例 chip、缺字段点名、超容一键降 ECC
- 窄屏（<640px）单列表单 + 吸底操作区

**Non-Goals:**
- 不改二维码编码与渲染算法（qrcodegen、`renderQr`）
- 不改历史记录触发机制（仍仅显式保存后记录）
- 不新增权限、网络、后端依赖
- P1/P2 功能（预设、SVG、扫码自检等）不在本 change 内

## Decisions

1. **双栏用 CSS Grid + `@media (min-width: 900px)`，断点 900px 而非 800px**
   右栏需要容纳 340px 预览 + 边距，左栏表单至少 420px，加上页面留白 900px 是可读下限。备选 800px（左栏过挤）与宿主面板宽度自适应（宿主面板尺寸不可控，900px 更稳）。**已实测确认**：用户环境 1920×1280，插件面板默认可用宽度 1220px，900px 断点成立。

2. **右栏 sticky 而非固定高度内滚动**
   `position: sticky; top: 16px; align-self: start` 实现简单、随主题/缩放稳健；备选的 `max-height + overflow:auto` 子滚动容器在 iframe 内滚动嵌套容易出双滚动条问题。

3. **容量阈值按「当前 ECC 级别的理论最大容量」计算**
   直接用 qrcodegen 内部 `getTotalDataCodewords(version, ecc)` 推导 byte 模式上限（7 字节头 + 长度指示），得到 `capacity(ecc)`；90% 阈值 = `0.9 * capacity`。备选：仅用保守值 738 字符（不准确，H 级别远低于此）或试编码探测（每次输入多一次完整编码，浪费）。理论容量是纯查表计算，无性能成本。注意：警示阈值是近似（实际容量还与文本内容有关，数字/拉丁字符更省），用途是「提前预警」而非精确边界，spec 不承诺精确性。

4. **缺字段点名复用空状态容器，不新增错误级 UI**
   `#empty` 已有空态容器，增加一个 i18n 化的动态文案分支（WiFi 缺 SSID → 「请填写网络名称」；名片缺姓名 → 「请填写姓名」）；`copy.*.toast.missing(f)` 文案已存在但从未使用，直接启用。判定顺序：页签完全无输入 → 通用空态 + chips；有部分输入但载荷为空 → 点名缺失字段。

5. **超容一键降级按钮直接操作 `style.ecc` + `syncStyleInputs()` + `scheduleGenerate(0)`**
   与「恢复默认样式」同一模式，不引入新的状态同步路径。降级后仍超容（ECC 已 L）时按钮不再出现，文案切换为缩短内容提示。

6. **示例 chip 生成临时示例内容，不写入历史**
   chip 只做「切页签 + 填值 + 生成」，用户清空即可丢弃；不调用 `pushHistory`（历史仍仅显式保存后记录，维持既有偏好）。

7. **vCard 折叠用 `<details>`（与样式盒同模式），折叠字段保持监听**
   `input`/`change` 监听绑定在元素上，与可见性无关，折叠不参与生成逻辑照常运行——无需额外状态同步。

8. **文案全部进 `copy.en/zh`，`applyLocale()` 统一注入**
   新增键：计数警示、示例 chips、缺失字段点名、降级按钮、吸底无新增文案。两语言同步补齐，避免出现硬编码英文。

9. **控件密度基准 32px（2026-11-09 用户反馈输入框偏高后收紧）**
   输入控件 `padding 7px 10px` + 13px 字号（高约 32px，原 41px）、textarea `min-height 84px`、标签 11.5px/下边距 4px、字段间距 8px、按钮 `padding 9px 14px`、预览 `min-height 240px`；「更多信息」`#vcMore` 去内层边框改为纯缩进 disclosure。定位：专业工具紧凑密度，双栏 gap 与预览 padding 不动，呼吸感保留。字段块约 72px → 58px（-20%）。

## Risks / Trade-offs

- [宿主面板实际宽度未知，900px 断点可能永不触发] → 实现后用 `dbx-plugin dev --port 5190` 实测宿主面板宽度，必要时将断点降为 800px（单点修改）
- [单文件 UI 改动面大，可能碰坏历史/样式逻辑] → 改动分两步提交：先 CSS 栅格与 DOM 结构调整，再 JS 行为（计数/空态/降级）；每步在宿主 + 独立浏览器双环境手工回归保存/复制/历史
- [容量理论值与实际可编码容量有偏差（数字模式更省）] → 警示只做提前预警，最终边界仍由 `encodeText` 抛错决定，两套机制并存不冲突
- [吸底操作区在沙箱 iframe 中可能与宿主底部边缘叠压] → 吸底仅在 <640px 断点启用，宿主桌面端不受影响；独立浏览器手机预览实测
- [右栏 sticky 在长历史展开时可能超高] → 历史列表已有 `max-height: 240px` 内滚动，右栏整体高度可控

## Migration Plan

纯前端单文件改动，随插件版本发布：`dbx-plugin package .` → 提交 candidate PR 到 dbx-store 常规流程。无数据迁移；历史条目结构不变，旧版本生成的历史在新 UI 中正常恢复。回滚 = 回退该版本插件包。
